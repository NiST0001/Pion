# 已完成工具回执自动回收

状态：源码已接入，构建安装与实际会话恢复另行验收。此次保留 SDK 和原 RPC 协议，仅增加完成回执回收及必要去重索引。

## 回收过程

- `AgentBridge` 在新工具调用登记前检查已回收 ID；重复 ID 继续拒绝，避免旧 start/end 转绑或重复计费。
- 内存回执达到 384 条时，调用 `reclaimCompletedToolReceipts` 批量回收。原 512 条容量继续约束仍保留的执行对象。
- 回收对象须满足 `state: ended`、`usageConsumed: true`，并且未被未结束、用量未消费或 ComputerUse 后续凭证依赖。
- 运行中后代需要的 parent/root 祖先链继续保留；已结束叶子可在父任务仍运行时回收，支持长 codemode 连续嵌套调用。
- ComputerUse 来源回执继续保留，维持原 retained、真实 entry/append 和后续操作校验。
- 一批 ID 记档事务成功后，才删除对应内存对象。索引读取或记档失败保留原证明，拒绝新的来源准入，并记录固定诊断。

聊天历史、工具结果、运行计费、子代理显示快照和原权限/计划/队列门保持各自原行为。已失败批次保持原结果，历史统计误记也保留原记录，后续恢复通过显式操作验收。

## 最小去重索引

`SqliteToolReceiptArchive` 使用 Node 内置 SQLite，位置为 `userData/tool-receipts/completed.sqlite`，无新增依赖。仅保存后端私有 scope 与完成或容量拒绝的 toolCallId，参数、正文、工具结果和凭证均省略。

精确磁盘查询保留历史防重放信息，内存只持有有界执行对象和约 1 MiB SQLite 页缓存。ID 数量沿真实调用增长，索引没有累计行数寿命阈值；磁盘不足等真实错误按保守失败处理。容量拒绝的 start 也封存 ID，避免以后释放容量时把旧拒绝调用重新绑定为新来源。

索引惰性创建，私有目录/新文件权限分别为 0700/0600；已知符号链接、非普通文件、文件身份变化、坏库和未知 schema 拒绝使用并保源。批次事务成功后发布；采用零锁等待，避免数据库竞争长时间阻塞主线程。文件及目录检查属于应用级约束，OS 沙箱另行验证。

scope 绑定真实 BackendRecord 与捕获的 RpcClient。普通停止永久移除该后端的来源归属后，关闭该 scope 并删除其去重行；后端重建使用新 scope。其他尚未明确退休的 scope 行继续保留。应用退出沿既有停止流程关闭索引。

## 验证边界

定向回归覆盖超过原累计容量的根/嵌套调用、跨轮重放、重复用量、真实在途满额、拒绝后重放、记档失败保表，以及 Cua/活动祖先保护。索引另覆盖作用域隔离、关闭重开、坏源/链接保留和批量事务。

Node 与 Electron 的 RunAsNode 模式已验证内置 SQLite 可用；该检查只覆盖无窗口的 SQLite 能力。GUI、打包、安装以及失败会话的真实恢复仍须独立验收。
